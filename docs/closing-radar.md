# BONG Market Brief — 장마감 주도주·테마 변화 감지

기존 `.github/workflows/main.yml`의 아침 08:00 브리핑을 유지하고,
별도 `closing.yml`에서 한국시간 평일 15:40 장마감 분석을 시작합니다.
16:10 / 16:40 실행은 데이터 지연·부분 발송 실패 및 특별 개장일 대응용입니다.
GitHub Actions 예약 실행은 지연되거나 누락될 수 있어 정확한 15:40 도착을 보장하지 않습니다.

## 적용 순서

1. GitHub 저장소 Settings → Secrets and variables → Actions에 `KRX_ID`, `KRX_PW`를 추가합니다.
   KRX 데이터 조회에 사용할 본인의 계정입니다. 대화나 코드에 비밀번호를 붙여넣지 않습니다.
2. 기존 아침 브리핑의 Secrets를 그대로 사용합니다:
   `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `KAKAO_REST_API_KEY`,
   `KAKAO_REFRESH_TOKEN`, 선택적 `KAKAO_CLIENT_SECRET`.
3. 변경 브랜치에서 Actions → **BONG Market Close** → Run workflow를 실행합니다.
   기본 `send=false`이며 보고서만 생성합니다. 거래일 장마감 10분 후 실행하세요.
   `bong-closing-report` artifact의 TXT/JSON을 확인합니다.
4. 실제 시세 날짜·종목 수·보고서가 맞으면 PR을 main에 병합합니다.
   main에 병합되면 평일 예약 실행 및 기존 수신처로 발송이 활성화됩니다.
   즉시 시험 발송은 Run workflow의 `send=true`를 사용합니다.

카카오에는 기존 방식대로 짧은 안내와 Telegram 봇 링크만 전송합니다.
전체 보고서는 Telegram에 전송하고 길면 나누어 보냅니다.
이 구현 작업에서는 실제 메시지를 발송하지 않았습니다.

## 판정 내용

| 항목 | 기준 |
| --- | --- |
| 시장 범위 | KRX KOSPI·KOSDAQ 전체 주식 시세; ETF/ETN 별도 목록은 조회하지 않음 |
| 주도주 후보 | 거래대금 300억원 이상, 당일 +2% 이상, 소속 지수 대비 +1%p 이상; 거래대금순 상위 10개 |
| 제외 | 거래정지/종가 0, 이름에 ‘스팩’, 종목코드 끝자리가 0이 아닌 종목(우선주 등 제외용 휴리스틱) |
| 거래대금 동반 | 직전 최소 5일~최대 20거래일 평균 대비 1.5배 이상 |
| 테마 | `config/closing.json`의 수동 지정 초기 10개 바스켓; 공식 분류·전 테마 자동발굴이 아님 |
| 테마 가격 | 구성종목 등락률 중앙값; 시장대비 강도는 각 종목 소속 지수 대비 초과등락률의 중앙값 |
| 상승 확산 | 구성종목 중 당일 상승 종목 비율 |
| 거래 집중도 | 테마 거래대금 / KOSPI·KOSDAQ 전체 조회 종목 거래대금 |
| 신규 강세/강세 지속 | 당일 강세 조건 충족 여부를 직전 거래일 조건과 비교 |
| 강세 이탈 | 전일 강세였으나 당일 조건에서 이탈 |
| 테마 내 교체 | 테마 거래대금 1위 종목의 전일 대비 변경 |

점수는 0~100의 설명 가능한 초기 규칙이며 수익률 검증이나 최적화 결과가 아닙니다.
`clip(x)`는 0~1 범위로 제한합니다.

```
40 × clip(시장대비 초과등락률[%p] / 5)
+ 25 × 상승종목 비율
+ 20 × clip(직전 평균 대비 거래대금 점유율 증가[%p] / 1)
+ 15 × clip(거래대금 배수 - 1)
```

**강세:** 실제 대표 등락이 양수이고 60점 이상이면서 시장대비 +1%p 이상, 상승종목 60% 이상,
거래대금 1.3배 이상, 점유율 변화 양수일 때.
**방향 판정:** 주가 흐름과 거래대금 증가를 구분합니다.
대표 등락이 -2% 이하이고 시장보다 1%p 이상 더 하락하며 상승 종목이 절반 미만이면 동반 약세입니다.
이때 거래대금이 1.5배 이상이면 ‘거래 급증 속 하락’으로 표시합니다.
주가가 하락한 테마에는 거래 증가 가산점을 주지 않고, 강세에는 실제 양의 등락이 필요합니다.
실제 상승·시장대비 +0.5%p·상승 종목 60% 이상이면 ‘상승 확산’,
하락 중 시장대비 +0.25%p 이상이면 ‘하락 속 선방’으로 구분합니다.
그 외 다수 하락은 약세, 나머지는 혼조입니다. 테마 구성종목이 하나라도 누락되면 그 테마 판정을 보류합니다.
거래대금 배수와 점유율 변화는 **당일을 제외**한 과거 자료로 계산합니다.
초기 6거래일을 자동 수집해 첫날부터 오늘/전일을 비교하고, 이후 최대 20일로 기준이 늘어납니다.
전일 점수는 현재 설정과 전일까지의 데이터로 다시 계산하므로 구성종목 변경 자체를 교체 신호로 쓰지 않습니다.

## 데이터와 운영상의 한계

- 거래대금은 매수/매도가 함께 성립한 거래 규모입니다. 실제 순유입·외국인/기관 순매수로 해석하지 않습니다.
- 15:40에는 투자자별 최종 수급이 아직 없을 수 있어 이 버전에서는 사용하지 않습니다.
- KRX 일별 데이터는 요청 시점에 제공되는 값입니다. 시간외 거래가 포함되거나 이후 정정될 수 있으며,
  이 버전은 15:30 정규장 전용 체결 데이터 또는 공급자의 확정 플래그를 제공하지 않습니다.
- 요청일 지수가 두 시장 모두 존재하고 전체 시세가 검증되어야 보고서를 만듭니다.
  휴일에 전일 데이터를 대신 가져오는 옵션은 끕니다. 데이터가 없으면 실패 처리하고 다음 예약 때 재시도합니다.
- XKRX 캘린더로 휴장일과 특별 개장시간을 확인합니다. 임시 휴장/일정 변경 시 캘린더 업데이트가 필요할 수 있습니다.
- 수동 테마 바스켓 밖의 새로운 테마는 자동 생성하지 않습니다. 시장 전체 주도주 후보는 따로 보여줍니다.
  한 종목의 복수 테마 편입이 가능하므로 테마 점유율을 모두 합산하지 않습니다.
- `bong-closing-state` artifact에 스냅샷과 날짜별 발송 성공 기록을 보관합니다(90일).
  API 키·비밀번호·토큰은 artifact에 저장하지 않습니다. 장기 중단/삭제 시 과거 6일을 재수집합니다.
- 채널별·메시지 조각별 성공 기록으로 일반적인 재실행 중복을 방지합니다.
  원격 전송 성공 직후 네트워크 단절/작업 강제 종료/상태 업로드 실패 시 중복이 생길 수 있습니다.
  외부 메시징 API와 로컬 상태를 원자적으로 갱신할 수 없으므로 exactly-once 보장은 없습니다.
- 재시도 때 이미 발송을 시작한 본문을 유지합니다. 당일 성공 후 재실행은 정정판을 다시 보내지 않습니다.
- Kakao 토큰 만료/갱신은 기존 아침 브리핑과 동일한 관리가 필요합니다.
  새 refresh token이 감지되면 토큰 값 없이 Secrets 갱신 필요 메시지를 출력합니다.

## 로컬 검증

```bash
pip install -r requirements-closing.txt pytest==9.1.1
PYTHONPATH=src python -m pytest tests/test_closing.py -q
PYTHONPATH=src python -m marketbrief.closing
```

기본 실행은 발송하지 않습니다. 과거일은 `--date YYYY-MM-DD`로 조회 가능하지만 발송 금지입니다.
`--fixture`는 `current` 스냅샷과 `history` 배열을 가진 JSON을 입력받으며 가상 데이터임을 표시합니다.
가상 데이터를 실제 발송하는 조합은 차단합니다.

검증 완료: 합성 데이터 기반 판정/퇴출/미래정보 배제/누락/휴장/발송 분할/부분 실패 재실행 테스트.
미검증: 실제 KRX 로그인·당일 전체 시세 응답, GitHub Actions 실운영, 실제 Telegram/Kakao 수신.

## 2026-10-07 가독성 개선

- 본문은 한 줄 결론 → 강한 업종 → 상대적으로 버틴 업종 → 크게 밀린 업종 → 전일 변화 → 상승 종목 5개 순입니다.
- 내부 점수·중앙값·점유율·상승비율은 본문에서 제거하고 JSON에 보관합니다.
- 관찰 5개 중 1개 상승처럼 종목 수를 표시하며, 종목 옆 퍼센트만 실제 당일 주가 등락률로 보여줍니다.
- 업종은 지정 종목 묶음 기준이며 산업 전체의 공식 지수나 ETF 수익률이 아닙니다.
- Telegram은 제목과 업종명을 굵게 표시합니다. 단순 거래대금 1위 변경을 주도주 교체처럼 강조하지 않습니다.
- 당일 발송 완료 기록은 유지합니다. 서식 변경만으로 기존 수신자에게 재발송하지 않습니다.
- 실제 2026-10-07 저장 시세로 새 보고서를 재생성해 확인했습니다.
